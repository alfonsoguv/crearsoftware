La verdad es que el mundo de las licencias de software libre es amplio y complicado. Actualmente, en las plantillas de [Velneo](http://www.velneo.es) usamos la licencia [EUPL](http://es.wikipedia.org/wiki/European_Union_Public_License).

Estamos dándole vueltas para ver si seguimos con esta licencia para las [Open Apps](http://v7.velneo.es/info/velneo-v7/velneo-open-apps-v7/) o si intentamos licenciarlas bajo un modelo más permisivo para el desarrollador.

Voy a clasificar las licencias de software libre según su permisividad.

## Licencias de software libre permisivas

Se puede crear una obra derivada sin que esta tenga obligación de protección alguna. Este tipo de licencias permitirían al desarrollador hacer lo que crea más oportuno con una Open App: podría licenciarla como privativa o abierta según considere más conveniente. Realmente no existe ninguna obligación con el uso del software libre que se le facilite; podría reutilizarlo, modificarlo, darlo abierto o cerrado.

*Las licencias más populares en este aspecto son:*

-   Academic Free License v.1.2.
-   Apache Software License v.1.1.
-   Artistic License v.2.0
-   Attribution Assurance License.
-   [BSD License](http://es.wikipedia.org/wiki/Licencia_BSD "Licencia BSD").
-   [MIT License](http://es.wikipedia.org/wiki/Licencia_MIT "Licencia MIT").
-   University of Illinois/NCSA Open Source License.
-   W3C Software Notice and License.
-   Zope Public License v.2.0
-   Open LDAP License v.2.7
-   Perl License.
-   Academic Free License v.3.0
-   Python License v.2.1
-   PHP License v.3.0
-   Q Public License v.1.0

Las más conocidas y usadas de este tipo de licencias son la **BSD** y la **MIT**.

## Licencias de software libre fuertes

Las licencias de software libre robustas fuertes, o con **copyleft fuerte**, contienen una cláusula que obliga a que las obras derivadas o modificaciones que se realicen al software original se deban licenciar bajo los mismos términos y condiciones de la licencia original.

En este aspecto son las más extremas en su uso. Cuando desarrollas apoyándote en software libre licenciado bajo este tipo de términos, debes aplicar la misma licencia a las obras derivadas. Todo lo que desarrolles a partir de estas licencias tiene que ser software libre. Por ejemplo, si utilizas una Open App para empezar un desarrollo, todo lo que hagas debería ser software libre. Nunca podrías realizar un software cerrado a partir de una Open App.

-   Common Public License v.1.0.
-   [GNU General Public License v.2.0](http://es.wikipedia.org/wiki/Licencia_p%C3%BAblica_general_de_GNU "Licencia pública general de GNU").
-   [GNU General Public License v.3.0](http://es.wikipedia.org/wiki/Licencia_p%C3%BAblica_general_de_GNU "Licencia pública general de GNU").
-   Eclipse Public License.
-   eCos License v.2.0
-   Sleepycat Software Product License.
-   Affero License v.1.0
-   Affero License v.2.0
-   OpenSSL License.

Evidentemente, la licencia robusta más conocida y usada en todo el mundo es la [GNU](http://es.wikipedia.org/wiki/GNU) de nuestro amigo [Stallman](http://es.wikipedia.org/wiki/Richard_Stallman).

## Licencias de software libre débiles

Las licencias de software libre robustas débiles, con **copyleft débil/suave** o híbridas, contienen una cláusula que obliga a que las modificaciones que se realicen al software original se deban licenciar bajo los mismos términos y condiciones de la licencia original, pero que las obras derivadas que se puedan realizar de él puedan ser licenciadas bajo otros términos y condiciones distintas. Permite enlazar productos libres con privativos.

Si se trata de un trabajo derivado, entonces los términos deben permitir la modificación por parte del usuario para uso propio y la utilización de técnicas de [ingeniería inversa](http://es.wikipedia.org/wiki/Ingenier%C3%ADa_inversa "Ingeniería inversa") para desarrollar dichas modificaciones. Definir cuándo un trabajo que usa un programa LGPL es un trabajo derivado o no es un asunto legal (ver el texto de la LGPL). Un ejecutable independiente que enlaza dinámicamente a una [biblioteca](http://es.wikipedia.org/wiki/Biblioteca_%28programaci%C3%B3n%29 "Biblioteca (programación)") se acepta por lo general como un trabajo que no es derivado de la biblioteca. Sería considerado como un trabajo que utiliza la biblioteca y se aplicaría el párrafo 5 de la LGPL.

Como podemos observar, el uso de estas licencias fue diseñado básicamente para licenciar bibliotecas.

Entre las licencias de esta categoría están:

-   [GNU Lesser General Public License v.2.1](http://es.wikipedia.org/wiki/Licencia_p%C3%BAblica_general_reducida_de_GNU "Licencia pública general reducida de GNU").
-   [Mozilla Public License](http://es.wikipedia.org/wiki/MPL "MPL")
-   Open Source License.
-   Apple Source License v.2.0
-   CDDL.
-   EUPL.
